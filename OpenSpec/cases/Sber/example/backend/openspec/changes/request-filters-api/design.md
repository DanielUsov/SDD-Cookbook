# Дизайн: request-filters-api

## Контекст

Список заявок реализован в `RequestController` и `RequestService`. Фича добавляет необязательные параметры отбора, поведение без параметров не меняется.

## Решения

| Решение | Почему |
|---|---|
| Параметры отбора собираются в один объект `RequestFilter` | контроллер и сервис не растут по числу параметров |
| Отбор строится динамически в репозитории (спецификации выборки) | нужны произвольные комбинации фильтров |
| Валидация периода и статусов в сервисном слое | одна точка для ошибок `INVALID_PERIOD`, `INVALID_STATUS` |
| Типы запроса и ответа берутся из сгенерированного кода по контракту Store | сборка падает при расхождении с контрактом |

## Риски

- Без индексов отбор по статусу и периоду медленный на больших данных. Закрывается соседним change `request-filters-indexes`.
- Порядок выдачи не должен меняться при добавлении фильтров, это проверяется тестом.

## Миграция

Не требуется: параметры необязательные, клиенты без фильтров продолжают работать.
