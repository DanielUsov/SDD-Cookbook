# Принципы работы со Store

Эта инструкция лежит в самом Store и описывает правила, общие для всех команд.

## Что такое Store

Общий репозиторий функциональных требований (ФТ). В нём описано, **что и как взаимодействует**: контракты, модель данных в общем виде, поведение, интерфейс. Как это реализовано внутри, Store не описывает.

## Правила

1. Аналитик пишет ФТ, не реализацию (никаких классов, таблиц конкретной СУБД, компонентов).
2. Одна фича, одна папка: `changes/HRPPRBCI-XXXX-суффикс/`.
3. Нет области, нет файла: если фича не затрагивает frontend, файла `FFRD.md` нет.
4. Каждая фича ссылается на свои бизнес-требования (БТ).
5. Любое изменение проходит PR и ревью: коллега-аналитик и по одному представителю затронутых частей.
6. Теги фич ставит Jenkins, тег релиза `x.y.z` ставит аналитик после архивации.

## Структура фичи

| Файл | Содержание |
|---|---|
| `FRD.md` | таблица, идея, основной механизм, ссылки на `BFRD.md` и `FFRD.md` |
| `BFRD.md` | изменения для backend |
| `FFRD.md` | изменения для frontend, включая интерфейс |
| `contracts/api.yaml` | фрагмент OpenAPI |
| `contracts/data-model.yml` | дельта логической модели данных |
| `contracts/integrations.*` | контракты внешних систем |
