# Встраивание Store в кодовый репозиторий

Инструкция для разработчика: как подключить Store к репозиторию сервиса.

## 1. Подключить submodule

```bash
git submodule add <адрес-store-в-bitbucket> openspec/store
```

Store физически лежит внутри проекта, а не где-то на вашей машине.

## 2. Закрепить на теге

Submodule **всегда пинится на тег**, не на коммит и не на ветку.

| Когда | На какой тег |
|---|---|
| фича в работе (в `changes/`) | тег фичи, например `HRPPRBCI-XXXX/v1` |
| фича архивирована | тег релиза Store, например `2.4.0` |

```bash
git -C openspec/store checkout HRPPRBCI-XXXX/v1
git add openspec/store
git commit -m "HRPPRBCI-XXXX: пин Store на HRPPRBCI-XXXX/v1"
```

## 3. Подключить схему и ссылку на инструкции

В `openspec/schemas/` лежит локальная схема (форк superpowers-bridge). В шагах `brainstorm` и `design` должно быть указание прочитать инструкцию своей части: `openspec/store/docs/Матрица-чтения-backend.md` или `…-frontend.md`.

## 4. Заполнять метаданные change

В начале `proposal.md` каждого change:

```yaml
---
jira-id: HRPPRBCI-XXXX
store-feature: HRPPRBCI-XXXX
store-version: HRPPRBCI-XXXX/v1
---
```

`jira-id` обязателен всегда. `store-feature` и `store-version` заполняются, только если у change есть фича в Store.

## 5. Подключить хук и codegen

Хук подключается автоматически при первой сборке. Шаг codegen в `Jenkinsfile` строит полный контракт и генерирует код.

## Если в Store появился новый тег вашей фичи

1. Аналитик пишет комментарий в Jira-задаче фичи.
2. Вы решаете, когда перейти: пините submodule на новый тег и обновляете `store-version`.
3. Агент сравнивает папку фичи между тегами (`git diff` между тегами) и вносит правки в артефакты change.
