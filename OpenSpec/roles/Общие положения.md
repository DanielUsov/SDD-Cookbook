Работа с артефактами разделена для нескольких ролей в команде, при необходимости могут брать на себя процессы смежных ролей.


|                        | Аналитик                                                                                  | Разработчик                                                                                                        | Тестировщик                                    |
| ---------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| Область взаимодействия | Store: ФТ фичи, контракты взаимодействия                                                  | кодовый репозиторий своей части (backend или frontend): реализация и локальный master spec                         | пока не описана                                |
| Основные артефакты     | `FRD.md`, `BFRD.md`, `FFRD.md`, `contracts/`, БТ в `business-requirements/`               | локальные changes (`proposal`, `design`, `specs`, `tasks`, `plan`, `verify`), локальный master spec, код           | пока не описаны                                |
| Принцип                | чёрный ящик: описывает взаимодействие, не реализацию                                      | отвечает за содержимое чёрных ящиков: как реализовать                                                              | —                                              |
| Что читает             | master spec Store, архив прошлых фич, БТ                                                  | файлы своей области Store на пинованном теге (по матрице чтения), при необходимости БТ                             | —                                              |
| Ручные операции в git  | PR в Store и тег релиза `x.y.z`                                                           | submodule, пин на тег, ветки gitflow, PR                                                                           | —                                              |
| Связь с трекером       | ID задачи фичи в таблице `FRD.md`, комментарий при изменении ФТ                           | `jira-id` в каждом change (обязательно всегда)                                                                     | —                                              |
